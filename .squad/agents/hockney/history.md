## Core Context

Condensed pre-2026-07-06 testing learnings (full detail in git history):

- **Config / server discipline:** verify UI against the **merged** config (`_config.yml,_config-dev.yml`) — dev-config-only omits `site.social-network-links` and gives false negatives (the old RSS-link failure was this drift, since rewritten to assert placement generically). Use **Jekyll's own server** (not `python -m http.server`) — only it serves the custom `404.html` with a real 404 status that `404.spec.ts` needs. Build to a fresh `-d` destination to sidestep the `incremental:true` staleness gotcha.
- **Test-authoring rules that stuck:** assert social-chip **placement** (links under `.nav-social`; footer exposes 0 `.social-chip`), never a hard-coded list. Archives specs assert feature behavior, not specific post slugs (content-coupled tests were removed); tag normalization is covered via `data-tags`. Image/content specs assert *"images that exist load; no broken images,"* never *"every recent post has an image"* (text-only posts are valid). Added a link checker (HTTP 200 per `a.archive-post-title`). Watch for a missing brace nesting later breakpoint rules inside `@media (prefers-reduced-motion)` — mobile UI then looks right in markup but fails in-browser.
- **Suite growth:** started at 6 specs, grew to **12** (added `command-palette` 13, `copy-code` 7, `post-nav` 2, `post-toc` 12, `reading-time` 1, `related-posts` 10). The `jekyll-workflow` skill's coverage table tracks this.
- **Repo hygiene:** `.tmp/impeccable` was once tracked as a `160000` gitlink with no `.gitmodules`, breaking `git submodule status` / CI — `.tmp/` stays gitignored. `remote_theme` removal verified clean (16/16 at the time); the stale `minima` line in `Gemfile.lock` is harmless (`github-pages` includes it transitively).
- **Redesign QA (2026-07-06):** baseline established BEFORE M1 (frozen `_site_baseline` build, served `--skip-initial-build --no-watch` on :4000 so it never races McManus's live edits), 65/65 green after first fixing one pre-existing content-coupled red in `images.spec.ts` (latest-10-posts assumed images; a text-only post = deterministic fail — assert *images that exist load*, never *every recent post has an image*). Restyle regression → 12 specs / 70 tests (landing 4→8, reading-time 1→2), then the polish pass → **71** (landing +1 focus-ring). **Font guard:** `getComputedStyle(el).fontFamily` returns the DECLARED stack regardless of webfont fetch — network-independent — so it locks CSS targeting (Fraunces on the three title slots, Inter on body). **Classify a red/overflow as new-vs-pre-existing by serving BOTH frozen builds on different ports** (`_site_baseline` :4001 vs redesign :4000) and probing the same path — this stopped me mislabeling the pre-existing 320px overflow as a regression. ### 2026-07-06 — Editorial-restyle polish pass: re-greened + drawer finding CORRECTED

Re-verified McManus's 3-fix polish (staged, not committed) against a fresh frozen build (`_site_redesign2`, Jekyll `--no-watch` serve on :4000, real 404s), then quantified the drawer follow-up McManus flagged. Scratch build deleted after; only `tests/` edited.

**Suite: 12 specs / 71 tests GREEN** (chromium, ~29s frozen). Grew 70→71: added one focus-ring test to `landing.spec.ts` (validated non-flaky via `--repeat-each=3` = 27/27). Per-file now: 404(2), archives(6), command-palette(13), copy-code(**6**), images(3), landing(**9**), post-nav(2), post-toc(12), reading-time(2), related-posts(10), scroll-to-top(1), search(5). Note: the jekyll-workflow coverage table was stale (claimed 65 total, copy-code 7, landing 4, reading-time 1) — refreshed to the verified 71.

**3-fix verification (all PASS):**
1. **Focus ring** — real keyboard **Tab** (not `.focus()`) to `.search-trigger` (hero ⌘K) and `.cmd-palette-hint` (nav ⌘K badge): both `:focus-visible=true`, computed `outline: 2px solid rgb(249,115,22)`. Before the polish these fell back to the UA default; now branded. Locked with a non-flaky Tab-*search* assertion (also guards keyboard-reachability).
2. **Long-URL wrap** — the two bare-`<autolink>` posts (`simple-explanation-private-pipeline-billing-vsts` 101-char link, `octopus-deploy-running-deployment-steps-parallel` 83-char) at 320px: `overflow-wrap: anywhere`, 0 `.blog-post a` offenders (max right 295/291px ≤ 320).
3. **Dead footer JS** — `_includes/footer-scripts.html` is now a Liquid comment; homepage entrance still animates via CSS (`.fade-in-up` → `animation-name: rise`, killed under reduced-motion), **0** console/pageerror on load.

**Drawer finding — corrected (this is the important one).** McManus's polish draft called the off-canvas `.mobile-drawer` the *dominant* 320px scroll cause (~35px, ~48 posts, "likely a transformed ancestor turning the fixed drawer into a scroll box"). **Isolation measurement disproves it:** hide the drawer + re-measure → `drawerContribution = 0px` on **all 48 posts**; there is **no transformed ancestor** above it (fixed, `translateX(110%)`, off-screen at x=[352,672]@320px, so it never extends the document scroller). The real overflow is **content on 9/48 posts** (39 clean): long unbroken `<em>`/`<code>` prose tokens (gitflow `*ProjectName*` = +362px), one unconstrained `<img>` (+39px), a wide code `<table>` (+41px). Root cause = `documentElement.scrollWidth - clientWidth` misses a `position:fixed` box, so an off-screen bounding box looks alarming but drives no scroll — must isolate, not infer. **Do NOT fix the drawer** (it isn't the cause) and the standing "no drawer assertions until stable" decision still holds. Follow-up is content-level (broaden wrap to non-link tokens / cap the one img+table), a Fenster design call — tracked in `hockney-polish-regression.md`, not this pass.

**Method + artifacts:** `tests/redesign/verify-polish.mjs` (new, standalone like `verify-redesign.mjs`) does the focus/wrap/console checks + the drawer `canScrollRight`/hide-to-attribute crawl. Screenshots **skipped** — the polish is invisible in every existing `tests/redesign/` frame (rings need keyboard focus; wrap only shows at 320px on long-URL posts; dead-JS removal is invisible).
